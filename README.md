# 原神好友状态监测器

**Genshin Friend Monitor** 是 Windows 本地工具，通过游戏画面截图和 OCR 记录好友资料、在线状态与千星奇域活动，支持账号隔离、人工校准以及 Excel / MySQL 导出。

程序通过鼠标、键盘操作可见的游戏界面；不读取游戏内存或好友存档，不接入游戏服务器接口。普通扫描在本地完成，只有主动执行 MySQL 导出时才会向配置的数据库发送好友记录。数据范围见 [隐私与数据说明](PRIVACY.md)。

> **需要完整的 16:9 游戏客户区，不含标题栏。** 建议使用 1280×720、1920×1080 或同等比例分辨率。比例不符时会提示并停止扫描。

## 安装与启动

- Windows 便携包：从 [GitHub Release](https://github.com/goldlzh/GenshinFriendMonitor/releases/latest) 下载 `GenshinFriendMonitor-windows-x64-v1.1.0.zip`，解压到可写目录，运行 `GenshinFriendMonitor.exe`，无需安装 Python。也可从 [Gitee 发行版](https://gitee.com/DM233/test_ocr_genshin/releases/latest) 下载分段包，按发行说明合并后解压。不要直接在压缩包中运行；游戏以管理员身份启动时，需右键以管理员身份运行扫描器。
- Windows 10 / 11，原神 PC 中文界面，建议窗口或无边框窗口模式。
- 64 位 Python 3.10+；开发验证环境使用 Python 3.13。依赖清单见 [requirements.txt](requirements.txt)，已记录的依赖组合见 [requirements-local-lock.txt](requirements-local-lock.txt)。
- 源码包不包含虚拟环境、个人配置、好友数据库、游戏字体或扫描截图。第一次使用需安装依赖。

在项目根目录打开 PowerShell：

```powershell
py -3.13 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
& .\.venv\Scripts\python.exe -m pip check
.\start.bat
```

| 入口 | 用途 |
| --- | --- |
| [start.bat](start.bat) | 普通启动 |
| [start-admin.bat](start-admin.bat) | 游戏以管理员身份运行时使用；由 Windows 提示授权 |
| [start-verify-admin.bat](start-verify-admin.bat) | 管理员启动，初始频率留空，便于单轮检查 |

所有入口都等待用户手动开始。`--scan-once` 只将初始频率留空，不会锁定后续选择。首次运行自动生成 `config.json`、`data/` 和 `logs/`。修改源码后需关闭旧程序并重新启动。

完整安装和迁移方法见 [LOCAL_SETUP.md](LOCAL_SETUP.md)。

## 开始使用

1. 启动游戏，保持画面可见。点击“查找窗口”；手动框选时须选择完整客户区，排除标题栏和黑边，且能唯一对应游戏窗口。
2. 保持右下角 UID 可见，点击“识别当前账号”。每个账号的好友列表独立存储。
3. 首次可先“快速扫描”再“识别全部UID”，也可直接点击“识别全部UID”。快速扫描前选择频率、“只扫描在线好友”和“保存好友主页截图”。默认预留准备时间；自动激活失败时，可点击游戏或 Alt+Tab 切回。
4. 扫描中避免手动操作或遮挡游戏。快速扫描只遍历一次列表；疑似改名时可能只打开该好友主页核验 UID，再返回原页继续。
5. 查看本轮完成结果和待校准项。双击昵称或签名原图人工填写；同名同签名无法区分时，先在游戏中设置不同备注。
6. 需要补全所有好友 UID 时，使用独立的“识别全部UID”。UID 未录齐不阻止正常使用，界面会提示可能导致身份匹配及统计不准确；补齐后提示自动消失。按需导出数据；备份前先停止扫描并关闭程序。

## 扫描频率与在线模式

| 频率（分钟） | 行为 | 是否累计时长 |
| --- | --- | --- |
| 留空 | 单次扫描 | 仅保存本次观察，不持续计时 |
| `0` | 一轮完成后立即开始下一轮 | 持续至失败、停止或关闭 |
| 正数，如 `0.5` | 按两轮开始时间计算间隔 | 按成功刷新后的有效期计时 |

不接受负数、非数字或无穷值。扫描超过设定间隔时，完成后再开始下一轮，不并发、不补跑积压任务。扫描期间频率、账号和相关选项锁定。

“只扫描在线好友”从顶部逐页处理完整卡片。“互动”“前往其大厅”“申请加入”等可靠按钮文字可确认在线；明确离线状态用于确认离线。一页出现离线好友时，仍处理本页后面的在线项，然后结束本轮。未知状态不视为离线边界，也不累计在线时间。此模式保留完整名单基线，不把未扫描项当作好友删除。

## 身份对应与人工校准

好友列表上方支持按**昵称或 UID**检索，可输入部分内容、用空格分隔多个关键词；回车或点击“选中匹配”会选中命中的行。查找已消失好友或手动录入资料时，先勾选“显示历史档案”。

- **昵称优先**：唯一可靠昵称关联已有本地档案；新好友可以先有本地 ID、暂时没有 UID。头像、等级、位置及界面模式改变不会触发全量 UID 扫描。
- **签名辅助改名**：只有非空、完整、可靠且唯一的签名指向一个已有 UID 的旧档案时，才单独打开主页核验。UID 不同不能继承候选的历史。失败保留待处理记录和截图，不每轮重复打开该主页。
- **同名歧义**：同名同签名且原图也无法区分时，提示设置不同游戏备注，保存独立待处理档案；不猜 UID，不累计存疑身份的时间。
- **文字无法识别**：昵称栏可直接显示完整原图。昵称、签名分别保留最新两版待校准图，供人工填写；确认空签名也可显式提交。人工签名与对应原图关联，同图下一轮仍读不清时继续使用校准值。
- **关联边界**：昵称和签名同时改变时不能可靠自动对应；截图也不能恢复不可见字符的编码。仅文字待核查与身份未知是不同状态，前者若档案可唯一确认，仍可记录可靠状态。

## 粘贴主页，单独录入好友

1. 选择资料所属账号，并停止当前扫描。手动截取好友主页，复制图片到剪贴板。
2. 点击好友列表中的“粘贴主页录入”，或将焦点放在好友表格后按 `Ctrl+V`。支持完整游戏画面和裁剪后的完整主页。
3. 本地 OCR 填入 UID、昵称、冒险等级和签名；对照原图核对后点击“确认录入”。未识别字段可手动补充，UID 与昵称必填。无法确认等级时保留“未知”；不勾选“保存 / 更新签名”时保留原签名，勾选后留空表示确认为空签名。
4. 相同 UID 更新已有档案。要为已有的无 UID 档案补资料，在“录入到”中明确选择该档案；不会仅因同名自动合并。新建资料保存在当前账号的历史档案中，成功录入后会自动显示并选中，后续扫描确认后进入当前名单。

截图仅用于资料录入，不推断当前在线状态或好友增减，不改写完整名单的成员范围。已有在线状态、计时和历史资料保留；取消对话框不保存。录入操作保留内部记录，不出现在“状态变动记录”中。

“保存这张主页截图”由录入对话框单独控制，保留粘贴的图片，沿用每人最新两版资料的规则；它不受扫描设置中的主页存档开关影响。此功能不上传图片到外部服务。

## 查看减少的好友

完整快速扫描会逐个比较前后名单中的好友档案，新增和消失分别统计。好友总数不变，也可能同时新增和减少；部分甚至全部好友尚未录入 UID，都不会因此跳过整轮比较。前后 UID 均完整时按 UID 比较，否则按已匹配的本地档案比较，不用行号或人数代替身份。

旧档案未出现在本轮完整名单时，“状态变动记录”显示红色“消失/可能被删”，包括已知的 UID、昵称和时间，并计入“变动”次数。该好友退出当前名单，但旧资料仍可勾选“显示历史档案”后查看、按昵称或 UID 搜索。事件表显示最近 500 条事件，同一好友持续缺席不会每轮重复登记消失。

首次完整扫描只建立比较基线；以后每轮成功扫描先保存增减事件，再更新基线。只扫描在线好友或扫描未完成时，不据未扫描项登记消失。“消失”表示旧档案本轮未被匹配到；改名、同名歧义等也可能影响对应，不能据此证明对方主动删除了自己。

## 两种界面与计时

每轮先检查主画面左下角：独立 `Enter` 对应普通界面，同一行另有 `Alt+N` 对应千星奇域。模式不明确时停止，避免混用字段。

“冒险等级”“千星等级”和“标签”独立保存。千星等级只在数字专属区域识别；未知读数不猜数字、不覆盖旧的已知等级。青蓝标签按背景动态划分，不能拼进昵称或签名。

“游玩奇域”“奇域游玩时间统计”“奇域游玩时段”分别显示当前活动、按活动累计时长与当日时段。只有千星界面确认的橙色活动文字参与计时，**“编辑内容中”也计入**。绿色活动、普通在线或无法确认的内容不算奇域游玩。频率留空不累计，停止、失败、到期、活动切换及跨午夜按普通计时规则结算。

正数频率到期仍未成功扫描时，按截止时刻结束计时；独立到期检查在 OCR 或暂停期间仍有效。重启不累计未运行期间。

“今日上线时段”按分钟显示：相邻扫描片段的结束与开始落在同一分钟时，合并显示首尾；明确观察到离线、未知状态，或停止、失败、重新启动监测时保留分段。合并只影响展示，扫描间隙不补入累计时长。旧记录也会整理，有明确离线事件的间隔仍保留；旧版未记录停止/失败的细分原因，同分钟的这类历史间隙无法可靠区分。

“状态变动记录”和 Excel 的“状态变动”页只显示上线、下线、新增、消失/可能被删：

- 每次开始扫描后，同一好友的首次观察只建立状态基线；已在线不记为刚上线，但仍按扫描频率正常统计在线时段。
- 同一次扫描任务的后续轮次明确观察到离线→在线或在线→离线时，才显示“上线”或“下线”。停止后重新开始会重新建立状态基线，名单增减基线及历史时段保留。
- 停止、失败、到期、首次确认在线、状态待确认、改名和手动录入等信息不显示为状态变动；内部结算记录继续保留，不影响时长与时段统计。
- 在线模式实际看到且能对应档案的离线卡片可确认下线；仅未扫描到的好友只结算计时，不生成下线事件。完整扫描确认旧档案缺席时记录消失，不额外推断下线。

这些都是截图观察和有效期估计，不能还原服务器精确上下线时间或扫描间隙的短暂活动。

## 截图与空间管理

| 内容 | 保留规则 |
| --- | --- |
| 扫描诊断截图 | 每账号保留最近两轮（含当前轮），更早轮次截图自动清理 |
| 好友主页 | “保存好友主页截图”开启时保留；每人最多最新两版昵称/签名内容 |
| 无法识别的昵称、签名 | 每人每字段最多最新两版不同内容，始终保存，不受主页开关影响 |
| 当前昵称匹配图与人工校准 | 保留用于后续身份对应，不随诊断轮次清理 |

自动采集的主页保存中央书本区域，手动粘贴录入保存用户确认的图片。同昵称和签名只刷新当前版，不因展柜画面变化新增一版；字段内容改变才追加。未知字段按原图判断内容，不能把两个空 OCR 结果当作相同内容。主页列支持查看、切换和缩放。

主页图片可按约 **150 KiB/张**粗略估算；例如 150 位好友各两张约 **44 MiB**。这是图片本身的估算，不含数据库页、字段图、日志、缓存和备份。关闭主页开关不删除旧图，也不影响 UID 核验。

完整 UID 的多个阶段及内部重扫属于同一顶层轮次。旧轮只清理图片，JSON/文本报告保留；并发活动轮次额外保护。清理不会删除正式好友档案、人工校准、数据库备份或导出文件。详细边界见 [PRIVACY.md](PRIVACY.md)。

## 配置、导出和备份

常用配置保存在本机 `config.json`；界面中的频率优先，手动修改配置后需重启。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `scan_frequency_minutes` | `null` | 留空单次、0 连续、正小数分钟间隔 |
| `online_only` | `false` | 只扫描在线好友 |
| `save_profile_screenshots` | `true` | 是否新增主页存档 |
| `save_scan_evidence` | `true` | 是否保存常规整页诊断图；必须保留的失败/待校准证据不受影响 |
| `startup_delay_seconds` | `3.0` | 启动准备时间 |
| `focus_wait_seconds` | `30.0` | 等待游戏获得焦点的上限 |
| `drag_hold_seconds` | `1.0` | 拖动到终点后继续按住的时间 |
| `ocr_threads` | `2` | OCR 推理线程数 |
| `nickname_font_path` | 空 | 可选的本机字库路径；字体不随项目分发 |
| `db_path` / `log_dir` | 项目下 `data/friends.db` / `logs` | 本地数据和诊断位置 |
| `export_dir` | 空 | Excel 输出目录；空值使用桌面 |

完整默认值见 [app/config.py](app/config.py)。旧 `scan_once_only` 不参与新调度；`scroll_mode` 等旧兼容参数不会改变默认快速流程的拖动方式。一般无需降低校验门槛或缩短动画等待。

Excel 导出好友信息和状态事件，允许 UID 留空。MySQL 是**用户主动执行的可选导出**，需要自行配置服务器和账号；按账号 UID 与好友 UID 隔离，跳过无有效好友 UID 的记录并提示。导出不会把 SQLite 的所有历史表或原图一并复制。昵称、签名文字属于导出数据，截图不嵌入导出文件。

关闭程序后备份整个 `data/`，并按需保存 `config.json` 和 `logs/`。配置可能含绝对路径和 MySQL 密码；日志、导出与数据库可能含账号和好友资料，不应提交到公开仓库。换机后重建 `.venv` 并检查配置路径。各账号数据库通常位于 `data/accounts/<账号UID>/friends.db`。

## 开发与验证

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

自动化测试覆盖身份关联、窗口保护、翻页连续性、UID 校验、事务、截图版本和计时边界，使用隔离数据及模拟游戏输入。离线截图回放与自动化测试不等于当前版本已在所有真实游戏环境验证；测试耗时也不是实际扫描速度。新版快速流程、多轮监测、不同系统与干净机器安装仍需对应环境验收。MySQL 真实服务器和打包后的目标机器兼容性不能仅由模拟测试证明。

本地截图可用 `scripts/replay_scan.py` 排查，运行前查看 `--help`；个人截图和报告不随源码分发。大模型提示词位于 `prompts/`，仅为未接入运行时的设计草案，当前扫描不调用大模型或云端 OCR。

PyInstaller 配置位于 [build.spec](build.spec)，可通过 [build.bat](build.bat) 构建，输出 `dist/GenshinFriendMonitor.exe`。`scripts/package_source.py` 使用允许的文件集合生成源码 ZIP；`scripts/package_windows.py` 将已构建程序、公开文档和依赖许可整理为 Windows 便携包。两种发布包均排除个人运行数据，配置模板见 [config.example.json](config.example.json)。便携包已在空白目录验证启动，其他目标机器的兼容性仍需实际验证。
